## =====================================================================
## PACCHETTI NVIDIA: VERIFICARE MACCHINA PER MACCHINA
## =====================================================================
##
## ⚠️ NON ESISTE una regola "su Linux si fa cosi'". Il parco macchine e' misto —
## Linux, Windows, macOS, ALCUNE CON NVIDIA E ALCUNE NO — e sbagliare costa in
## entrambe le direzioni:
##   - installare le build CUDA dove non c'e' NVIDIA  -> GIGABYTE di peso morto
##   - installare le build CPU dove la NVIDIA C'E'    -> GPU sprecata, tutto lento
##
## Quindi: PRIMA si guarda l'hardware, POI si sceglie. Ogni volta, su ogni macchina.
##
## --- PASSO 1: c'e' una GPU NVIDIA su QUESTA macchina? ---
##
##   nvidia-smi                       # se risponde: NVIDIA presente e driver attivo
##   lspci | grep -i nvidia           # Linux, anche senza driver
##   # macOS: mai. Niente CUDA su Mac da anni -> per torch si usa MPS (Apple Silicon).
##
## --- PASSO 2a: SE C'E' NVIDIA -> build CUDA (i default vanno bene) ---
##
##   pip install torch                # su Linux il default PyPI E' GIA' la build CUDA
##   pip install xgboost              # nccl serve davvero -> lasciarlo
##   # Su Windows il default e' CPU: per la GPU serve l'index CUDA esplicito, es.
##   #   pip install torch --index-url https://download.pytorch.org/whl/cu126
##   # Verifica: python -c "import torch; print(torch.cuda.is_available())"  -> True
##
## --- PASSO 2b: SE NON C'E' NVIDIA -> build CPU (vanno chieste esplicitamente) ---
##
##   pip install torch --index-url https://download.pytorch.org/whl/cpu   # -> 2.13.0+cpu
##   pip install xgboost-cpu          # NON 'xgboost' (vedi trappola sotto)
##   # con uv, per i tool isolati:  uv tool install --torch-backend=cpu ...
##   # Verifica: python -c "import torch; print(torch.__version__)"  -> deve finire in +cpu
##
## --- LE DUE TRAPPOLE, quando NON c'e' NVIDIA ---
##
## 1) `torch` su Linux: il wheel PyPI di default e' la build CUDA e si trascina
##    nvidia-cudnn, cuda-toolkit, triton... svariati GB. Su Windows il default e'
##    CPU, ecco perche' il problema non si era mai visto prima di Linux.
##    -> installare torch dall'index CPU PRIMA dei pacchetti che lo richiedono
##       (es. docling): dopo, pip lo trova gia' soddisfatto e non ritenta con CUDA.
##
## 2) `xgboost` dichiara su Linux, INCONDIZIONATAMENTE:
##        nvidia-nccl-cu12; platform_system == 'Linux'
##    senza controllare se una GPU NVIDIA esista: 400 MB. NCCL serve solo al training
##    distribuito multi-GPU. Su Windows la dipendenza non c'e'.
##    -> `xgboost-cpu`: stessa versione, deps numpy+scipy, wheel da 5 MB invece di 400.
##       Il modulo importato resta `xgboost`, il codice non cambia.
##         pip uninstall -y xgboost nvidia-nccl-cu12 && pip install xgboost-cpu
##
## --- CONTROLLO, da rifare dopo ogni installazione grossa ---
##
##   pip list | grep -iE 'nvidia|cuda|triton'
##   # macchina CON NVIDIA:  legittimo trovarci roba
##   # macchina SENZA:       deve essere VUOTO
##
## Se rispunta qualcosa dove non deve, trovare il colpevole prima di disinstallare a caso:
##   python -c "
##   import importlib.metadata as md
##   for d in md.distributions():
##       for r in (d.requires or []):
##           if 'nvidia' in r.lower() or 'cuda' in r.lower():
##               print(d.metadata['Name'], '->', r)"
##
